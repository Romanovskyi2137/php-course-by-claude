# 05. Рядки та кодування

> Що ти вже вмієш: базові рядкові операції з іншої мови · Що додає ця тема: інтерполяцію
> PHP-стилю, heredoc, і найважливіше — **байти проти символів** для UTF-8 (критично для
> української) · ~20 хв

## 1. Якщо ти прийшов з JS / Python / Java

- Одинарні й подвійні лапки в PHP **не рівнозначні**, на відміну від JS/Python:
  подвійні лапки інтерполюють змінні й екранування (`\n`, `\t`), одинарні — ні
  (майже, розділ 3.1). Це відрізняється від JS, де `'...'` і `"..."` ідентичні.
- **PHP-рядок — це послідовність байтів**, а не символів Unicode (на відміну від
  Python 3 `str`, де рядок — послідовність кодових точок за замовчуванням). Для
  UTF-8 (кирилиця, емодзі) звичайні `str*`-функції рахують **байти**, а не літери —
  для цього є окреме сімейство `mb_*` (розділ 3.4).

## 2. Ключові терміни

- **Interpolation (інтерполяція)** — підстановка значень змінних прямо в рядок
  у подвійних лапках: `"Привіт, {$name}!"`.
- **Heredoc / Nowdoc** — багаторядкові рядкові літерали: heredoc інтерполює
  (як подвійні лапки), nowdoc — ні (як одинарні).
- **Multibyte string (багатобайтовий рядок)** — рядок, де один "символ" (напр.
  кирилична літера) кодується кількома байтами в UTF-8.

## 3. Теорія

### 3.1 Одинарні vs подвійні лапки

```php
$name = 'Ada';

echo 'Привіт, $name';      // буквально: Привіт, $name — без інтерполяції
echo "Привіт, $name";       // Привіт, Ada — з інтерполяцією
echo "Привіт, {$name}!";     // те саме, {} явно позначає межі виразу — обов'язково
                              // для складних виразів: "{$obj->prop}", "{$arr['key']}"
echo 'Рядок\nз \n';           // буквально: Рядок\nз \n (escape НЕ спрацьовує)
echo "Рядок\nз \n";            // реальний перенос рядка
```

### 3.2 Heredoc / Nowdoc

```php
$name = 'Ada';

$html = <<<HTML
    <p>Привіт, {$name}!</p>
    <p>Багаторядковий текст без екранування лапок.</p>
    HTML;               // закриваючий маркер може бути з відступом з PHP 7.3+

$raw = <<<'TEXT'
    Тут $name НЕ інтерполюється — це nowdoc, аналог одинарних лапок.
    TEXT;
```

Heredoc зручний для великих шаблонів тексту з підстановками без купи `.` для
конкатенації та без екранування внутрішніх лапок.

### 3.3 Ключові `str_*` функції

```php
strlen('hello');                 // 5 — довжина в БАЙТАХ
str_contains('hello world', 'wor');   // true (PHP 8.0+)
str_starts_with('hello', 'he');        // true (PHP 8.0+)
str_ends_with('hello', 'lo');           // true (PHP 8.0+)
strtolower('HELLO');                     // 'hello'
str_replace('l', 'L', 'hello');           // 'heLLo'
trim('  hi  ');                            // 'hi'
explode(',', 'a,b,c');                      // ['a', 'b', 'c']
implode('-', ['a', 'b', 'c']);                // 'a-b-c'
sprintf('%s має %d балів', 'Ada', 42);         // 'Ada має 42 балів'
number_format(1234567.891, 2);                  // '1,234,567.89'
```

`str_contains`/`str_starts_with`/`str_ends_with` — фічі PHP 8.0. До того доводилось
писати `strpos($h, $n) !== false` — саме тому в легасі-коді ти побачиш `strpos`
там, де сьогодні писали б `str_contains`.

### 3.4 UTF-8: байти проти символів

```php
$word = 'Привіт';                 // 6 кириличних літер, у UTF-8 кожна — 2 байти

strlen($word);                       // 12 — довжина в БАЙТАХ, не літерах!
mb_strlen($word);                     // 6  — довжина в СИМВОЛАХ

strtoupper($word);                     // 'Привіт' — НЕ змінюється! strtoupper не знає UTF-8
mb_strtoupper($word);                   // 'ПРИВІТ' — працює правильно

substr($word, 0, 3);                     // обірваний, "поламаний" байтовий фрагмент
mb_substr($word, 0, 3);                   // 'При' — коректні перші 3 символи
```

**Правило для цього курсу (і будь-якого PHP-коду з нелатинським текстом): для
тексту, що може містити кирилицю, завжди `mb_*`-версія функції, якщо вона існує.**

## 4. Підводні камені

- `strlen()`/`substr()`/`strtoupper()` на кириличному тексті — тихий, підступний
  баг: код не падає, просто дає неправильний результат (обрізає посеред літери,
  не змінює регістр). Немає винятку, який би на це вказав.
- `"Привіт, $name!"` без фігурних дужок працює для простих змінних, але
  `"Ціна: $item->price"` **не** інтерполює властивість без `{}` — вийде
  буквально `$item` + `->price` як текст. Завжди `{$item->price}` для
  чогось складнішого за просту змінну.
- `number_format()` за замовчуванням використовує кому як роздільник тисяч і
  крапку як десяткову — для іншої локалі потрібні явні аргументи
  (третій/четвертий параметри).

## 5. Сучасний PHP 8.3+

`str_contains`/`str_starts_with`/`str_ends_with` (8.0) прибрали більшість
приводів писати `strpos(...) !== false` для перевірки на входження підрядка —
використовуй їх за замовчуванням у новому коді.

## 6. Контекст екосистеми

Будь-який PHP-проєкт з підтримкою кирилиці (а це майже весь SNG-веб) **зобов'язаний**
мати розширення `mbstring` увімкненим і `mb_internal_encoding('UTF-8')` десь у
бутстрапі — інакше пошук, обрізання заголовків, лічильники символів масово ламаються
саме на кириличному контенті.
