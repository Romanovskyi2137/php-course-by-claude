# 17. Traits (трейти)

> Що ти вже вмієш: одиничне успадкування (тема 15) · Що додає ця тема:
> механізм "горизонтального" перевикористання коду між непов'язаними класами
> · ~20 хв

## 1. Якщо ти прийшов з JS / Python / Java

- Traits — найближчий PHP-аналог Python mixins чи Kotlin/Scala traits (звідки
  й назва запозичена). У Java подібну роль частково відіграють `default`-методи
  інтерфейсів (Java 8+), але PHP traits потужніші — можуть мати й стан
  (приватні властивості), не лише поведінку.
- На відміну від множинного успадкування (Python), traits **не є типами** —
  `$obj instanceof SomeTrait` не працює. Трейт — це буквально механізм
  "вставити ці методи в тіло класу", не окрема сутність в ієрархії типів.
- JS не має прямого еквіваленту — найближче, можливо, підмішування методів
  через `Object.assign(prototype, mixin)`, але без перевірки на етапі
  оголошення й без вирішення конфліктів на рівні мови.

## 2. Ключові терміни

- **Trait (трейт)** — набір методів (і опційно властивостей), який можна
  "вставити" в тіло будь-якого класу через `use TraitName;`, без обмежень
  одиничного успадкування.
- **Horizontal reuse (горизонтальне перевикористання)** — перевикористання
  коду між класами, що не повʼязані спільним предком (на відміну від
  "вертикального" перевикористання через `extends`).
- **Trait conflict (конфлікт трейтів)** — ситуація, коли клас використовує
  два трейти з однойменними методами; вирішується явно через `insteadof`/`as`.

## 3. Теорія

### 3.1 Оголошення й використання

```php
trait Loggable
{
    private array $log = [];

    public function log(string $message): void
    {
        $this->log[] = $message;
    }

    public function logs(): array
    {
        return $this->log;
    }
}

class Article
{
    use Loggable;   // методи log()/logs() і властивість $log тепер частина Article
}

$article = new Article();
$article->log('created');
$article->logs();   // ['created']
```

Трейт можна використати в **будь-якій кількості** непов'язаних класів —
`Article`, `Order`, `User` можуть усі `use Loggable;`, не маючи спільного
предка.

### 3.2 Кілька трейтів одночасно

```php
trait Timestamped
{
    private ?string $createdAt = null;

    public function touch(): void
    {
        $this->createdAt = date('Y-m-d');
    }
}

class Article
{
    use Loggable, Timestamped;   // обидва трейти одразу
}
```

### 3.3 Конфлікти імен: `insteadof` і `as`

```php
trait Greets
{
    public function hello(): string { return 'Hello from Greets'; }
}

trait Speaks
{
    public function hello(): string { return 'Hello from Speaks'; }
}

class Robot
{
    use Greets, Speaks {
        Greets::hello insteadof Speaks;    // явно кажемо, чий hello() перемагає
        Speaks::hello as speaksHello;        // а метод Speaks зробити доступним під іншою назвою
    }
}

(new Robot())->hello();         // 'Hello from Greets'
(new Robot())->speaksHello();     // 'Hello from Speaks'
```

Без явного `insteadof` для конфліктного методу PHP кине `Fatal error` при
оголошенні класу — на відміну від множинного успадкування Python (де є
неявний MRO), PHP вимагає явного рішення.

### 3.4 Абстрактні й статичні члени в трейтах

```php
trait Comparable
{
    abstract public function value(): int;   // трейт МОЖЕ вимагати метод від класу

    public function isGreaterThan(self $other): bool
    {
        return $this->value() > $other->value();
    }
}
```

Трейт може оголосити `abstract`-метод, який зобов'язаний реалізувати клас,
що його використовує, — механізм, схожий на "трейт очікує співпраці від
класу-хазяїна".

## 4. Підводні камені

- Traits — не інтерфейси: `$obj instanceof Loggable` **не працює** (кине
  помилку "клас не знайдено" або поверне `false`, залежно від контексту) —
  якщо потрібна перевірка типу, трейт треба комбінувати з окремим
  інтерфейсом.
- Надмірне використання трейтів ("трейт на кожен метод") робить клас важким
  для розуміння: щоб знати повний список методів класу, доводиться шукати
  по кількох файлах трейтів — це прихована залежність, схожа на магію.
- Трейт зі своїм станом (приватні властивості) може непомітно конфліктувати
  з властивістю класу-хазяїна з такою самою назвою — PHP не завжди явно
  попереджає про це на етапі оголошення.

## 5. Сучасний PHP 8.3+

Traits — стабільна фіча з PHP 5.4, суттєвих змін у 8.x не було. Головна
сучасна порада — не зловживати ними: composition через окремі сервіси
й Dependency Injection (тема 41) часто прозоріший вибір, ніж трейт, коли
йдеться про справжню бізнес-логіку, а не суто технічну "домішку"
(логування, timestamps, серіалізація).

## 6. Контекст екосистеми

PHPUnit (тема 44) активно використовує трейти для домішування допоміжної
поведінки в тестові класи (`use RefreshDatabase;`, `use MatchesSnapshots;`
у Laravel-тестах) — типовий, легітимний випадок використання: технічна
"домішка", не бізнес-логіка.
