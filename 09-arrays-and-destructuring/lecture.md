# 09. Масиви та деструктуризація

> Що ти вже вмієш: масиви/списки/словники з іншої мови · Що додає ця тема: PHP-масив
> як єдину структуру "і список, і словник одночасно", і value semantics · ~25 хв

## 1. Якщо ти прийшов з JS / Python / Java

- У JS/Python/Java є окремі типи для списку (`Array`/`list`) і словника
  (`Object`/`Map`/`dict`). **У PHP є лише один тип `array`**, який одночасно
  впорядкована послідовність і хеш-мапа — індексований і асоціативний масив
  це буквально одна й та сама структура даних із різними ключами.
- Масиви в PHP копіюються **за значенням** при присвоєнні (`$b = $a`), як
  структури Swift/примітиви, а **не за посиланням**, як обʼєкти/масиви в
  JS/Python/Java. `$b = $a; $b[] = 1;` не змінює `$a`. Це критична відмінність.
- Деструктуризація `[$a, $b] = $pair;` схожа на `const [a, b] = pair` у JS,
  але PHP не має "rest"-синтаксису (`...rest`) у деструктуризації — тільки
  в аргументах функцій (тема 08).

## 2. Ключові терміни

- **Value semantics (семантика значення)** — при копіюванні масиву копіюється
  весь вміст (концептуально), а не посилання на нього.
- **Copy-on-write (копіювання при записі)** — оптимізація: PHP **не** копіює
  масив фізично одразу при `$b = $a`, а лише коли один з них справді
  змінюється — але для коду це виглядає так, ніби копія відбулась одразу.
- **List destructuring (деструктуризація списку)** — `[$a, $b] = $array;` або
  `['x' => $x] = $array;` для розпаковування значень в окремі змінні.

## 3. Теорія

### 3.1 Масив як хеш-мапа

```php
$indexed = [10, 20, 30];               // ключі 0, 1, 2 — неявно
$assoc = ['a' => 1, 'b' => 2];           // явні рядкові ключі
$mixed = [0 => 'x', 'name' => 'y', 5 => 'z'];   // ключі можуть бути змішані

$next = [10, 20, 30];
$next[] = 40;                              // додає з ключем 3 (наступний вільний int)
$next[10] = 'stray';                        // можна "стрибнути" на будь-який ключ
$next[] = 'after';                           // ключ 11 — наступний ПІСЛЯ найбільшого числового
```

Ключі можуть бути `int` або `string`; числові рядкові ключі (`'5'`) автоматично
приводяться до `int`.

### 3.2 Value semantics: копіювання, не посилання

```php
$a = [1, 2, 3];
$b = $a;          // "копія" — концептуально незалежний масив
$b[] = 4;

var_dump($a);     // [1, 2, 3] — не змінився!
var_dump($b);     // [1, 2, 3, 4]
```

Це фундаментально відрізняється від `$b = $a` для **об'єктів** (тема 12) —
об'єкти в PHP завжди присвоюються за "handle" (посиланням на той самий обʼєкт).
Масив — значення, об'єкт — посилання. Це одне з найважливіших концептуальних
розрізнень PHP для розробника з мов, де все — обʼєкт (Python) або все —
значення за замовчуванням, крім масивів (Java).

Щоб масив передавався/присвоювався за посиланням явно — потрібен `&`:
`$b = &$a;` (робить `$b` і `$a` буквально одним і тим самим масивом).

### 3.3 Вкладеність

```php
$user = [
    'name' => 'Ada',
    'address' => [
        'city' => 'London',
        'zip' => '12345',
    ],
];

$user['address']['city'];   // 'London'
```

Вкладені масиви — стандартний спосіб представити структуровані дані до того,
як заведуться DTO-обʼєкти (тема 12) чи прийде JSON з API (тема 25).

### 3.4 Деструктуризація

```php
$pair = [10, 20];
[$x, $y] = $pair;             // $x = 10; $y = 20;
[, $second] = $pair;            // пропускаємо перший елемент: $second = 20

$user = ['name' => 'Ada', 'age' => 30];
['name' => $name, 'age' => $age] = $user;   // деструктуризація за ключами

foreach ([[1, 'a'], [2, 'b']] as [$id, $letter]) {   // деструктуризація прямо в foreach
    // $id, $letter доступні тут
}
```

### 3.5 Spread у літералах масивів (PHP 8.1+: зі строковими ключами)

```php
$defaults = ['timeout' => 30, 'retries' => 3];
$overrides = ['retries' => 5];

$config = [...$defaults, ...$overrides];   // ['timeout' => 30, 'retries' => 5]
                                             // пізніший spread перезаписує однакові ключі
```

### 3.6 `array_is_list()`

```php
array_is_list([1, 2, 3]);          // true — послідовні int-ключі з 0
array_is_list([1 => 'a', 0 => 'b']);   // false — ключі не по порядку
array_is_list(['a' => 1]);           // false — не числовий ключ
```

Корисно перед `json_encode` (тема 25): список кодується як JSON-масив `[...]`,
а асоціативний масив — як JSON-обʼєкт `{...}`.

## 4. Підводні камені

- Value semantics масивів vs reference semantics обʼєктів — джерело плутанини №1
  для новачків з Python/JS, де "все передається за посиланням". У PHP масив,
  переданий у функцію без `&`, **безпечно копіюється** — функція не може
  випадково змінити оригінал (на відміну від об'єктів, де може).
- `$next[] = 40;` після `$next[10] = 'stray';` дає ключ `11`, а не `4` —
  PHP рахує "наступний ключ" від **найбільшого числового ключа в масиві**,
  а не від кількості елементів.
- `array_merge()` **перенумеровує** числові ключі (індексовані масиви
  зливаються, а не перезаписуються по позиції) — на відміну від оператора
  `+`, який зберігає ключі лівого операнда. Детальніше — тема 10.

## 5. Сучасний PHP 8.3+

Spread-оператор у літералах масивів зі строковими ключами (8.1) — сучасна
заміна `array_merge()` для об'єднання конфігурацій, коротша й читабельніша.

## 6. Контекст екосистеми

Value semantics масивів — одна з причин, чому PHP-код традиційно "функціональний
за замовчуванням" для роботи з даними: передав масив у функцію — не думай про
побічні ефекти, як довелось би в JS з обʼєктами/масивами.
