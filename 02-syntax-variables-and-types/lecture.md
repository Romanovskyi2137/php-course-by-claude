# 02. Синтаксис, змінні й типи

> Що ти вже вмієш: базовий синтаксис якоїсь мови · Що додає ця тема: специфіка PHP-синтаксису,
> констант і типової системи · ~20 хв

## 1. Якщо ти прийшов з JS / Python / Java

- PHP-код всередині `.php`-файлу обов'язково обгортається тегом `<?php ... ?>`. Усе поза
  тегом — це просто текст, який виводиться як є (звідси й походить PHP — шаблонизатор,
  що вміє в код). Закриваючий `?>` у чистих `.php`-файлах з кодом (без HTML після)
  **прийнято не писати** — це запобігає випадковим пробілам/переносам після тега, які
  ламають вивід заголовків (детальніше в темі 28).
- Змінні завжди з `$`: `$name`, а не `name` чи `let name`. Це не косметика — `$name`
  і `name` (константа/функція) — це буквально різні простори імен.
- На відміну від JS (`var`/`let`/`const` для оголошення), у PHP змінна **не оголошується
  окремим ключовим словом** — вона зʼявляється в момент першого присвоєння.
- Немає block scope, як `let` у JS: змінна, оголошена всередині `if`, живе в усій
  функції/файлі — детальніше в розділі 3.4.

## 2. Ключові терміни

- **Type juggling (жонглювання типами)** — автоматичне приведення типів PHP під час
  операцій. Детально — тема 03; тут лише знайомимось із самими типами.
- **Type declaration (декларація типу, type hint)** — явна вказівка типу параметра
  чи повернення функції, напр. `function f(int $x): string`.
- **`declare(strict_types=1)`** — директива файлу, що вимикає неявне приведення
  скалярних типів **при передачі аргументів у функції з type hints цього файлу**.

## 3. Теорія

### 3.1 Теги, вивід, коментарі

```php
<?php
// однорядковий коментар
# теж однорядковий (рідше використовують)
/* багаторядковий коментар */

echo "Привіт";      // echo — не функція, а мовна конструкція, можна без дужок
print "Привіт";     // print теж конструкція, але завжди повертає 1 (можна в виразах)
echo "a", "b", "c"; // echo приймає кілька аргументів через кому — швидше за конкатенацію
```

### 3.2 Змінні

```php
$name = 'Ada';       // з'являється тут, до цього не існувала
$age = 30;
$age = 'тридцять';   // одна й та сама змінна може змінити тип — PHP динамічно типізований
```

Динамічна типізація змінної $\ne$ відсутність типів у мові: типи існують і перевіряються
під час виконання (а з `strict_types` — частково і на межі викликів функцій).

### 3.3 Константи: `const` vs `define()`

```php
const APP_NAME = 'PHP Course';        // на етапі компіляції, тільки на верхньому рівні
                                       // файлу або всередині класу
define('APP_VERSION', '1.0');         // на етапі виконання, працює й умовно (в if)

echo APP_NAME;   // без $ — константи не змінні
```

`const` — типовий вибір за замовчуванням (швидше, перевіряється раніше). `define()`
потрібен рідко: коли ім'я чи значення константи обчислюється динамічно.

### 3.4 Область видимості: немає block scope

```php
if (true) {
    $x = 42;
}
echo $x; // 42 — працює! змінна "витекла" з if назовні, бо scope тут — функція/файл, не блок

function demo(): void {
    $y = 1;
}
// echo $y; // Error: змінна $y не існує тут — межа scope це функція, а не файл
```

### 3.5 Скалярні типи й `null`

PHP має 4 скалярних типи (`int`, `float`, `bool`, `string`), складені (`array`, `object`),
спеціальні (`null`, `callable`, `iterable`, `mixed`, `never`, `void` — останні для
декларацій, не для значень) і `resource` (легасі, напр. відкритий файл-дескриптор).

```php
var_dump(42);        // int(42)
var_dump(4.2);        // float(4.2)
var_dump('hi');       // string(2) "hi"
var_dump(true);       // bool(true)
var_dump(null);       // NULL
gettype(42);           // 'integer' (історична назва, не 'int'!)
```

### 3.6 `strict_types` на практиці

```php
declare(strict_types=1);

function addInts(int $a, int $b): int {
    return $a + $b;
}

addInts(1, 2);     // 3 — ок
addInts('1', 2);   // TypeError! Без strict_types рядок '1' тихо став би 1.
addInts(1.0, 2);   // TypeError навіть для float, що виглядає як ціле.
```

Без `declare(strict_types=1)` PHP **намагається** привести переданий аргумент до
потрібного типу (coercive mode) — це джерело багів, яких немає в TypeScript/Java.
Тому це перший рядок практично в кожному файлі цього курсу.

## 4. Підводні камені

- `gettype()` повертає історичні назви (`'integer'`, `'boolean'`, `'double'` — навіть
  для `float`!), а не `'int'`/`'bool'`/`'float'`, які використовуються в type hints.
  Для читабельного виводу зазвичай пишуть власне мапування (це і є частина завдання).
- `strict_types` — властивість **файлу, звідки зроблено виклик**, а не файлу, де функція
  оголошена! Якщо `sum_strict()` оголошена у файлі зі `strict_types=1`, але викликана
  з файлу без цієї директиви, виклик буде **нестрогим** — коерція типів спрацює. Це
  найчастіша плутанина з цією фічею: strict-режим не "прилипає" до функції назавжди,
  він діє в момент виклику, залежно від того, звідки викликають.
- Так само `strict_types` стосується **лише виклику функцій**, а не внутрішніх операцій
  на кшталт `$x = "5" + 3;` (це все ще жонглювання типами, тема 03).
- `const` не можна використовувати всередині `if`/функції на верхньому рівні файлу —
  для умовного визначення потрібен `define()`.

## 5. Сучасний PHP 8.3+

У PHP 8.3 з'явились типізовані константи класів (`public const int LIMIT = 10;`,
тема 14). Глобальні константи (`const`/`define`) типів не мають — тільки значення.

## 6. Контекст екосистеми

Практично весь сучасний PHP-код (Laravel, Symfony, будь-який серйозний пакет
на Packatist) пишеться з `declare(strict_types=1);` як стандартом де-факто —
PSR цього формально не вимагає, але статичні аналізатори (PHPStan, тема 39)
відчутно ефективніші зі strict-режимом.
