# 12. Класи та об'єкти

> Що ти вже вмієш: класи/об'єкти з іншої мови · Що додає ця тема: PHP-специфіку
> `$this`, видимості, конструктора й — найважливіше — reference semantics об'єктів
> на противагу value semantics масивів (тема 09) · ~25 хв

## 1. Якщо ти прийшов з JS / Python / Java

- На відміну від масивів (тема 09, value semantics), **об'єкти в PHP завжди
  передаються й присвоюються за "handle"** (посиланням на той самий об'єкт) —
  так само, як у Python/Java/JS. `$b = $a;` для об'єктів **не** створює копію.
  Це узгоджується з твоєю інтуїцією з інших мов — на відміну від масивів.
- `$this` в PHP схожий на `this` у JS-методах (не на `self` у Python, який
  передається явним першим параметром) — доступний неявно всередині методів.
- Немає перевантаження конструкторів (кілька `__construct` з різними сигнатурами,
  як у Java) — один клас має рівно один конструктор. Альтернативні способи
  створення об'єкта роблять через статичні фабричні методи (тема 14).

## 2. Ключові терміни

- **Visibility (видимість)** — `public`/`protected`/`private`, хто може
  звертатись до властивості/методу: будь-хто / клас+нащадки / лише сам клас.
- **Nullsafe operator `?->`** — `$obj?->prop` повертає `null` замість помилки,
  якщо `$obj` є `null`, і не викликає метод/не звертається до властивості.

## 3. Теорія

### 3.1 Оголошення класу, конструктор, `$this`

```php
class Point
{
    private float $x;
    private float $y;

    public function __construct(float $x, float $y)
    {
        $this->x = $x;
        $this->y = $y;
    }

    public function x(): float
    {
        return $this->x;
    }

    public function length(): float
    {
        return sqrt($this->x ** 2 + $this->y ** 2);
    }
}

$p = new Point(3.0, 4.0);
$p->length();   // 5.0
```

`$this` доступний тільки всередині нестатичних методів і посилається на
конкретний екземпляр, на якому метод викликано.

### 3.2 Типізовані властивості й "uninitialized"

```php
class User
{
    public string $name;   // типізована властивість БЕЗ значення за замовчуванням
}

$u = new User();
echo $u->name;   // Error: типізована властивість не ініціалізована!
```

На відміну від нетипізованих властивостей (де за замовчуванням `null`),
типізована властивість без явного значення й без присвоєння в конструкторі —
у стані "uninitialized", і звернення до неї кидає `Error`, а не повертає `null`.

### 3.3 Видимість

```php
class BankAccount
{
    private float $balance = 0.0;    // тільки цей клас

    public function deposit(float $amount): void   // будь-хто
    {
        $this->balance += $amount;
    }

    protected function auditLog(): void { /* ... */ }  // цей клас + нащадки
}
```

### 3.4 Об'єкти — reference semantics

```php
class Counter { public int $value = 0; }

$a = new Counter();
$b = $a;              // $b і $a — ОДИН і той самий об'єкт, не копія!
$b->value = 5;

echo $a->value;   // 5 — теж змінився, бо це той самий об'єкт
```

Щоб отримати незалежну копію об'єкта — потрібен явний `clone $a` (тема 13).
Це протилежність поведінці масивів (тема 09) — тримай цю різницю в голові
щоразу, коли передаєш дані у функцію/метод.

### 3.5 Nullsafe operator `?->`

```php
class Address { public function __construct(public string $city) {} }
class Profile { public ?Address $address = null; }

$profile = new Profile();
$city = $profile->address?->city;   // null, без Error — коротко замість:
// $city = $profile->address !== null ? $profile->address->city : null;
```

`?->` можна ланцюжити: `$user?->profile?->address?->city` — весь ланцюжок
зупиняється на `null` і повертає `null`, не викликаючи наступні кроки.

### 3.6 Деструктор

```php
class FileHandle
{
    public function __destruct()
    {
        // викликається, коли об'єкт більше нікому не потрібен (garbage collection)
    }
}
```

Деструктори в PHP використовують значно рідше, ніж у C++/C# — momент виклику
не гарантований одразу (залежить від збирача сміття), і для звільнення ресурсів
частіше пишуть явний метод `close()`.

## 4. Підводні камені

- Reference semantics об'єктів "ламає" інтуїцію тих, хто щойно засвоїв value
  semantics масивів (тема 09) — легко забути, що `$b = $a` для об'єкта НЕ
  створює копію, і випадково змінити спільний стан.
- Звернення до неініціалізованої типізованої властивості — `Error`, а не
  тихий `null`. Це на краще (явна помилка замість прихованого бага), але
  несподівано для тих, хто звик, що "неоголошене — це null".
- `?->` зупиняє **весь** ланцюжок на першому `null`, а не тільки поточний крок:
  `$a?->b->c` — якщо `$a` є `null`, `$b->c` взагалі не обчислюється (а не
  впало б з помилкою "звернення до властивості null").

## 5. Сучасний PHP 8.3+

Nullsafe `?->` (8.0) замінив громіздкі ланцюжки `isset()`/потрійних перевірок,
типові для PHP 7 і раніше. У легасі-коді ти побачиш `isset($a) && isset($a->b) ? ... : null`
там, де сьогодні написали б один рядок з `?->`.

## 6. Контекст екосистеми

Reference semantics об'єктів — фундамент того, як працює Dependency Injection
(тема 41): передаючи об'єкт-залежність у конструктор, ти передаєш посилання на
той самий сервіс, а не копію — усі частини застосунку, що отримали цей сервіс,
працюють з одним і тим самим станом (наприклад, одним і тим самим
підключенням до БД).
