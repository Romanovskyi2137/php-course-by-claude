# 01. Історія PHP, філософія мови і як виконується запит

> Що ти вже вмієш: писати код іншою мовою (JS/Python/Java/...) · Що додає ця тема: контекст,
> без якого решта курсу буде набором довільних фактів · ~25 хв

## 1. Якщо ти прийшов з JS / Python / Java

- **Node.js** тримає один процес, який живе довго і ділить пам'ять між запитами (event loop).
  PHP (у класичній моделі) створює **нове чисте виконання на кожен HTTP-запит** — жодного
  спільного стану між запитами за замовчуванням. Це і біль (немає in-memory кешу з коробки),
  і суперсила (витік пам'яті в одному запиті не вбиває сервер).
- **Python/Java** зазвичай мають один спосіб щось зробити (`the Zen of Python`). PHP історично
  ріс знизу — від «функцій, які вирішують конкретну проблему» — тому в стандартній бібліотеці
  часто є 2-3 способи зробити одне й те саме, з непослідовними назвами (`strpos` vs
  `str_contains`, `array_map($fn, $arr)` vs `usort($arr, $fn)` — порядок аргументів різний).
  Тримай це в голові: непослідовність — не твоя помилка, це історичний баланс.
- Те, що в Java/C# називається "runtime" (JVM/.NET CLR), у PHP називається **Zend Engine** —
  але ти майже ніколи не взаємодієш з ним напряму, на відміну від JVM-тюнінгу.

## 2. Ключові терміни

- **Zend Engine** — інтерпретатор, що виконує PHP-байткод. Аналог JVM для Java чи V8 для JS.
  Названий на честь Andi Gutmans та Zeev Suraski, авторів переписаного руками ядра PHP 3→4.
- **SAPI (Server API)** — інтерфейс, через який PHP спілкується з зовнішнім світом: `cli`
  (термінал), `cli-server` (вбудований дев-сервер), `fpm-fcgi` (продакшн через nginx).
  `PHP_SAPI` — константа, яка каже, в якому SAPI ти зараз виконуєшся.
- **Shared-nothing architecture (архітектура без спільного стану)** — модель, де кожен запит
  отримує чисту пам'ять і глобальний стан не переживає запит (якщо явно не використати
  зовнішнє сховище — Redis, файл, БД, opcache-змінні).
- **OPcache** — байткод-кеш: компілює `.php`-файл у байткод один раз і тримає в спільній
  пам'яті, щоб наступні запити не парсили файл заново. Не плутати з кешем даних.

## 3. Теорія

### 3.1 Коротка історія

- **1994–1995** — Rasmus Lerdorf пише набір CGI-скриптів на C, "Personal Home Page Tools"
  (PHP/FI), щоб рахувати відвідування власної сторінки. Це не мова програмування в задумі —
  це набір утиліт, і саме тому в PHP так багато прагматичних, не завжди "чистих" рішень.
- **1997–1998, PHP 3** — Zeev Suraski та Andi Gutmans переписують парсер із нуля, PHP стає
  повноцінною мовою, а не набором скриптів.
- **2000, PHP 4** — новий рушій, Zend Engine 1, стабільний фундамент для росту вебу нульових.
- **2004, PHP 5** — справжнє ООП (до цього класи були, але іграшкові): інтерфейси, абстрактні
  класи, `try/catch`, `PDO` для БД. Це PHP, який уже впізнає розробник з інших мов.
- **PHP 6** — офіційно **не вийшов**. Спроба вбудувати Unicode на рівні рушія провалилась
  через продуктивність і складність; проєкт заморозили. Номер версії "згорів".
- **2015, PHP 7** — переписаний з нуля рушій (Zend Engine 3, проєкт "phpng"), **вдвічі швидший**
  і вдвічі менш прожерливий по пам'яті, ніж PHP 5.6, без зміни мови для більшості коду.
  Додались скалярні type hints, `return` типи, `spaceship operator` `<=>`, `null coalescing` `??`.
- **2020, PHP 8.0** — JIT-компіляція (опційна, найбільше дає для CPU-важких задач, не для
  типового веб-запиту), `match`, named arguments, `nullsafe` `?->`, attributes, union types,
  constructor property promotion.
- **8.1** — enums, readonly-властивості, `never`, fibers, first-class callable syntax.
- **8.2** — readonly-класи, DNF-типи, `null`/`false`/`true` як самостійні типи.
- **8.3** — типізовані константи класів, `json_validate()`, покращення `#[Override]`.

### 3.2 Філософія: прагматизм понад чистоту

PHP свідомо жертвує концептуальною стрункістю заради "просто працює для вебу".
Наслідки, які ти відчуєш у цьому курсі:
- Немає єдиного стилю неймингу в стандартній бібліотеці (`snake_case` функції, але
  `CamelCase` класи в SPL).
- Багато поведінки визначено історично, а не логічно (детальніше — теми 03-04 про
  порівняння типів).
- Водночас — низький поріг входу, величезна стандартна бібліотека "з коробки"
  (без npm install: дати, регулярки, JSON, файли, сесії, поштові функції) і
  найбільша частка вебу з усіх бекенд-мов.

### 3.3 Де сьогодні живе PHP

- **WordPress** — керує близько 40% усіх сайтів у світі. Це PHP.
- **Laravel, Symfony** — сучасні фреймворки, де побудований величезний шматок
  корпоративного і стартап-вебу. Symfony-компоненти лежать всередині Laravel,
  Drupal, phpBB та багатьох інших проєктів.
- **Wikipedia/MediaWiki**, **Etsy** (історично), **Slack** (бекенд довгий час писали
  на Hack — діалекті PHP від Meta) — PHP і його похідні працюють у величезному масштабі,
  спростовуючи міф "PHP не масштабується".
- Хостинг: shared-hosting індустрія 2000-х існує майже виключно завдяки PHP —
  завантажив `.php`-файл по FTP, і воно просто працює, без збірки й деплою.

### 3.4 Як виконується один запит

```
Браузер → nginx → php-fpm (пул PHP-воркерів) → твій index.php виконується з нуля
                                                → формує $_GET/$_POST/сесію заново
                                                → віддає HTML/JSON
                                                → процес PHP "забуває" все й чекає наступний запит
```

У розробці замість nginx+php-fpm часто використовують вбудований сервер:

```bash
php -S localhost:8000 -t public/
```

Це піднімає легкий HTTP-сервер без окремого налаштування nginx — зручно для навчання
і локальної розробки, **не для продакшну** (однопотоковий, без багатьох оптимізацій).

### 3.5 Як ти запускаєш PHP у цьому курсі

```bash
php check.php          # виконує файл через SAPI "cli"
php -a                 # інтерактивний REPL (обмежений, без автодоповнення)
php -r 'echo PHP_VERSION;'   # виконати рядок коду напряму
```

## 4. Підводні камені

- **"PHP помер"** — стереотип із форумів 2010-х. Реальність: PHP 8 у 3-8 разів швидший
  за PHP 5.6 на тому ж коді, і за даними W3Techs досі стоїть за більшістю бекендів вебу.
  Стереотип живе довше за факти.
- Плутанина SAPI: код, що чудово працює в `php -S` (dev-сервер), може поводитись інакше
  під `php-fpm` (наприклад, заголовки, буферизація виводу) — про це детальніше в темі 28.
- `PHP 6` як номер версії ти можеш зустріти лише в старих статтях — офіційного релізу
  не існує, це не помилка друку.

## 5. Сучасний PHP 8.3+

Курс орієнтований на PHP 8.3+. Це не "ще одна версія" — це мова з типізацією майже
на рівні TypeScript (union/intersection types, readonly, enums), продуктивністю
близькою до компільованих мов для CPU-задач (JIT) і сучасним синтаксисом (`match`,
`?->`, named arguments). Легасі-код на PHP 5 виглядає помітно інакше — де це важливо,
курс показуватиме обидва варіанти.

## 6. Контекст екосистеми

Laravel та Symfony ховають shared-nothing модель за абстракціями (роутер, DI-контейнер),
але розуміння того, що кожен запит — це нове виконання з нуля, пояснює, чому в цих
фреймворках є окремі механізми для "речей, які мають пережити один запит" (кеш, сесія,
черги) — на відміну від Node.js, де досить тримати змінну в пам'яті процесу.
