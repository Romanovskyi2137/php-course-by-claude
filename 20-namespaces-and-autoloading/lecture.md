# 20. Простори імен та автозавантаження

> Що ти вже вмієш: `import`/`package`-системи з іншої мови · Що додає ця тема:
> PHP-специфіку — простір імен це просто префікс імені, а автозавантаження
> потрібно **написати самому** (до Composer, тема 38) · ~25 хв

## 1. Якщо ти прийшов з JS / Python / Java

- PHP `namespace` **не** відповідає файлам автоматично, на відміну від Python
  (де модуль = файл) чи Java (де пакет = директорія — обов'язково). У PHP
  `namespace App\Domain;` — це просто текстовий префікс до імен усередині
  файлу; яка структура директорій — питання угоди (PSR-4, тема 38), не
  вимога мови.
- Немає `import`/`require`, вбудованого в мову для завантаження класів за
  назвою, як `import` у Python чи `import` у Java. PHP класи завантажуються
  або явним `require`, або через **автозавантажувач** — функцію, яку
  реєструє сам розробник (чи Composer за нього, тема 38), яка викликається,
  коли PHP зустрічає невідомий клас.
- `use` у PHP — це **аліас для імені**, а не імпорт модуля з боку (як
  `import { x } from 'y'` у JS) — воно не виконує код іншого файлу, лише
  скорочує, як писати повне імʼя класу.

## 2. Ключові терміни

- **Namespace (простір імен)** — префікс, що групує повʼязані імена класів/
  функцій і запобігає конфліктам назв між бібліотеками.
- **FQN (Fully Qualified Name, повне ім'я)** — повне імʼя з усіма
  просторами імен: `\App\Domain\Product`.
- **Autoloading (автозавантаження)** — механізм: коли PHP зустрічає
  невідомий клас, він викликає зареєстровану функцію-автозавантажувач,
  передаючи їй повне імʼя класу; та функція вирішує, який файл `require`.

## 3. Теорія

### 3.1 Оголошення й використання

```php
// файл classes/Domain/Product.php
namespace App\Domain;

class Product
{
    public function __construct(public string $name, public float $price) {}
}
```

```php
// в іншому файлі
use App\Domain\Product;

$p = new Product('Книга', 10.0);    // короткий алiас завдяки use
$p2 = new \App\Domain\Product('Ще книга', 5.0);   // або повне імʼя напряму, з \
```

### 3.2 Правила іменування

```php
namespace App\Domain;

class Product {}

// Усередині App\Domain функції без префікса — це App\Domain\функція, ЯКЩО вона
// існує; якщо ні, PHP автоматично шукає у ГЛОБАЛЬНОМУ просторі:
strlen('hi');   // спрацює навіть у namespace App\Domain — fallback на глобальні функції
```

Цей fallback стосується лише **функцій і констант**, не класів — невідомий
клас без `\`-префіксу шукається спочатку в поточному неймспейсі.

### 3.3 Автозавантаження вручну: `spl_autoload_register`

```php
spl_autoload_register(function (string $class): void {
    // $class тут — повне імʼя, напр. 'App\Domain\Product'
    $relative = str_replace('App\\', '', $class);           // 'Domain\Product'
    $path = __DIR__ . '/classes/' . str_replace('\\', '/', $relative) . '.php';
                                                                // 'classes/Domain/Product.php'
    if (is_file($path)) {
        require $path;
    }
});

$product = new \App\Domain\Product('Книга', 10.0);   // клас підвантажується САМ,
                                                         // без явного require нагорі файлу
```

Функція, передана в `spl_autoload_register`, викликається **лише коли**
PHP реально зустрічає невідомий клас — файли, які ніде не використовуються,
взагалі не завантажуються (лінива, "ледача" загрузка).

### 3.4 `use function`/`use const`

```php
namespace App\Domain;

use function App\Support\format_currency;
use const App\Support\DEFAULT_CURRENCY;

format_currency(1000);   // короткий виклик замість App\Support\format_currency(1000)
```

## 4. Підводні камені

- Забутий `\` перед іменем вбудованого класу всередині свого простору
  імен — `new Exception()` усередині `namespace App;` шукає `App\Exception`,
  а не глобальний `\Exception`, і кине `Error: Class "App\Exception" not found`.
  Правильно: `new \Exception()` явно, або `use Exception;` нагорі файлу.
- Структура директорій "App\Domain\Product" → "classes/Domain/Product.php" —
  це **угода**, яку реалізує саме твій автозавантажувач; PHP сам по собі
  не знає нічого про відповідність простору імен і шляху до файлу.
- Реєстрація кількох автозавантажувачів через `spl_autoload_register` —
  нормально, PHP викликає їх по черзі, поки один не підвантажить клас.

## 5. Сучасний PHP 8.3+

У реальних проєктах **ніхто не пише автозавантажувач вручну** (окрім
навчальних цілей, як тут) — Composer генерує оптимізований PSR-4
автозавантажувач автоматично (тема 38). Але розуміння того, як він працює
під капотом, критичне для діагностики "Class not found" помилок.

## 6. Контекст екосистеми

PSR-4 (стандарт від PHP-FIG, тема 39) — формалізована угода про
відповідність `Namespace\ClassName` → шлях до файлу, яку реалізує
Composer autoloader. Те, що ти пишеш вручну тут, — спрощена версія того
самого принципу.
