# 03. Жонглювання типами та порівняння

> Що ти вже вмієш: скалярні типи PHP (тема 02) · Що додає ця тема: як PHP порівнює й
> приводить типи "під капотом" — головне джерело "дивних" багів у мові · ~25 хв

## 1. Якщо ти прийшов з JS / Python / Java

- Якщо в тебе був досвід з JS — інтуїція про `==` частково перенесеться, але **правила
  інші й змінювались між PHP 7 і PHP 8** (розділ 3.3). Не покладайся на пам'ять з JS.
- Python і сучасний Java/TypeScript в основному уникають неявного приведення типів
  між "несумісними" типами. PHP історично робив це агресивно — і це джерело №1
  "чому PHP дивний" скарг. PHP 8 суттєво це прибрав (особливо для порівняння
  рядок-число), але `==` все одно приводить типи.
- Практичне правило для цього курсу й для будь-якого сучасного PHP-коду:
  **типово використовуй `===`, а не `==`**, якщо немає явної причини для навпаки.

## 2. Ключові терміни

- **Type juggling (жонглювання типами)** — автоматичне приведення операндів до
  спільного типу під час операції (`+`, `==`, `.`, умова в `if`).
- **Truthiness (приведення до bool)** — правила, за якими будь-яке значення
  інтерпретується як `true`/`false` в умові.
- **Loose comparison (нестроге порівняння)** — `==`/`!=`, з жонглюванням типів.
- **Strict comparison (строге порівняння)** — `===`/`!==`, без жонглювання: різні типи
  → одразу `false`.

## 3. Теорія

### 3.1 `==` vs `===`

```php
0 == false;        // true  — обидва "порожні"/falsy
0 === false;        // false — різні типи (int vs bool)
'1' == 1;           // true  — рядок приводиться до числа
'1' === 1;           // false
null == false;      // true
[] == false;         // true — порожній масив falsy
```

### 3.2 Truthiness: що вважається `false`

Falsy-значення в PHP: `false`, `0`, `0.0`, `'0'` (!), `''` (порожній рядок),
`[]` (порожній масив), `null`. **Все інше** — truthy, включно з `'0.0'` і `'false'`
(рядки, що не дорівнюють рядку `'0'`, — truthy!).

```php
if ('0') { /* не виконається */ }
if ('0.0') { /* виконається! рядок '0.0' truthy, на відміну від '0' */ }
if ('false') { /* виконається! це непорожній рядок */ }
```

### 3.3 PHP 8: порівняння рядок-число змінилось

До PHP 8 (`0 == 'abc'` було `true` — рядок приводився до числа `0`). Це вважалось
найнебезпечнішим наслідком жонглювання типами: перевірка `$id == 'foo'` могла
випадково збігтись з `$id = 0`. **PHP 8 це виправив**:

```php
0 == 'foo';    // PHP 7: true.  PHP 8: false — тепер число приводиться до рядка.
0 == '0';      // true в обох версіях — '0' валідний числовий рядок
0 == '';       // PHP 7: true.  PHP 8: false
```

Нове правило PHP 8: якщо рядок **не** є числовим рядком, число приводиться до рядка
(а не навпаки), і порівнюються вже рядки.

### 3.4 Spaceship operator `<=>`

```php
1 <=> 2;   // -1 (менше)
2 <=> 2;   // 0  (рівні)
3 <=> 2;   // 1  (більше)
```

Головне застосування — компаратори для `usort()` (тема 10): `fn($a, $b) => $a <=> $b`.

### 3.5 `isset`, `empty`, `is_null`

```php
$data = ['a' => null, 'b' => 0];

isset($data['a']);   // false! ключ є, але значення null — isset вважає це "не встановлено"
isset($data['b']);   // true — 0 це не null
isset($data['c']);   // false — ключа взагалі немає
array_key_exists('a', $data); // true — на відміну від isset, бачить null-значення

empty($data['b']);   // true — 0 вважається "порожнім" для empty(), навіть якщо ключ є
empty($data['x']);   // true — і для неіснуючого ключа теж, без warning (на відміну від
                      // прямого звернення до $data['x'])
```

### 3.6 Явні касти

```php
(int) '42px';    // 42 — PHP бере числовий префікс рядка
(int) 'px42';     // 0  — немає числового префіксу
(float) '3.14abc'; // 3.14
(bool) '0';        // false
(array) 'x';        // ['x'] — скаляр обгортається в масив з одним елементом
(string) true;      // '1'
(string) false;     // '' — порожній рядок, не 'false'!
(string) null;       // '' — теж порожній рядок
```

## 4. Підводні камені

- `(string) false === ''`, а не `'false'`. Дуже частий баг при дебазі — `echo $bool;`
  для `false` виводить нічого.
- `empty()` не кидає notice для неіснуючих ключів, на відміну від прямого `$arr['x']`
  без `isset`, тому `empty()` — зручний, але легко приховує помилку в назві ключа.
- `in_array($needle, $haystack)` за замовчуванням використовує **нестроге** порівняння!
  `in_array(0, ['a', 'b', 'c'])` в PHP < 8 повертало `true` через `'a' == 0`. У PHP 8
  це виправлено так само, як `==` вище, але звичка передавати третій аргумент
  `true` (строгий режим) залишається хорошою практикою.

## 5. Сучасний PHP 8.3+

Зміна правил порівняння рядок-число (розділ 3.3) — одна з найважливіших змін PHP 8
для якості коду. Якщо читаєш легасі PHP 5/7 код, будь-яке порівняння змінної з
числовим літералом (`$id == 0`, `$type == 1`) варто перевіряти на цю різницю поведінки.

## 6. Контекст екосистеми

Статичні аналізатори (PHPStan/Psalm, тема 39) на високих рівнях строгості спеціально
попереджають про використання `==` там, де можливий `===` — це найчастіше
автоматично виявлювана категорія багів у PHP-проєктах.
