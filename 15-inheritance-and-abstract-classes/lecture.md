# 15. Успадкування та абстрактні класи

> Що ти вже вмієш: `extends`/абстрактні класи з іншої мови · Що додає ця тема:
> PHP-специфіку `parent::`, коваріантність типів, і коли композиція краща
> за успадкування · ~20 хв

## 1. Якщо ти прийшов з JS / Python / Java

- Одиничне успадкування (`extends` тільки одного класу) — як у Java/C#,
  на відміну від Python (множинне успадкування через MRO). Для "домішування"
  поведінки з кількох джерел у PHP є traits (тема 17), не множинне
  успадкування класів.
- `parent::__construct()` потрібно викликати **явно**, якщо хочеш виконати
  логіку батьківського конструктора — PHP не робить це автоматично
  (на відміну від Java, де батьківський конструктор викликається неявно,
  якщо не вказано інше).
- Абстрактні класи (`abstract class`) не можна інстанціювати напряму —
  так само, як `abstract class` у Java чи `ABC` в Python.

## 2. Ключові терміни

- **Abstract method (абстрактний метод)** — метод без тіла, оголошений в
  абстрактному класі; кожен конкретний нащадок **зобов'язаний** його
  реалізувати.
- **Template Method (патерн "шаблонний метод")** — метод батьківського класу,
  що визначає загальний алгоритм, делегуючи окремі кроки абстрактним методам,
  які реалізують нащадки.
- **Covariance (коваріантність)** — нащадок може звузити тип, що повертає
  перевизначений метод, до більш конкретного підтипу.

## 3. Теорія

### 3.1 `extends` і `parent::`

```php
class Animal
{
    public function __construct(protected string $name) {}

    public function describe(): string
    {
        return "Тварина на ім'я {$this->name}";
    }
}

class Dog extends Animal
{
    public function __construct(string $name, private string $breed)
    {
        parent::__construct($name);   // явний виклик батьківського конструктора
    }

    public function describe(): string
    {
        return parent::describe() . ", порода {$this->breed}";   // розширення, не заміна
    }
}
```

### 3.2 Абстрактні класи й методи

```php
abstract class Shape
{
    abstract public function area(): float;         // немає тіла — контракт

    public function describe(): string                // звичайний метод — спільна логіка
    {
        return sprintf('Площа: %.2f', $this->area());
    }
}

new Shape();   // Error: Cannot instantiate abstract class Shape

class Circle extends Shape
{
    public function __construct(private float $radius) {}

    public function area(): float
    {
        return M_PI * $this->radius ** 2;
    }
}

(new Circle(2.0))->describe();   // 'Площа: 12.57' — describe() із батька, area() з нащадка
```

Це і є **Template Method**: `describe()` не знає, ЯК рахується площа —
знає лише, ЩО з нею робити, коли вона є.

### 3.3 Коваріантність типів повернення

```php
class Animal
{
    public function reproduce(): Animal { return new Animal(); }
}

class Dog extends Animal
{
    public function reproduce(): Dog { return new Dog(); }   // звужує Animal -> Dog, дозволено!
}
```

Дозволено, бо кожен `Dog` — це `Animal`, тож звуження типу повернення не
порушує контракт батьківського методу (той, хто очікував `Animal`, отримає
щонайменше `Animal`-сумісний обʼєкт).

### 3.4 `final`

```php
class Config
{
    final public function get(string $key): mixed { /* ... */ }   // не можна перевизначити
}

final class Settings { /* ... */ }   // клас узагалі не можна успадкувати
```

### 3.5 Коли композиція краща за успадкування

```php
// Успадкування: "Duck IS-A FlyingAnimal" — ламається, якщо зʼявиться Penguin
class FlyingAnimal { public function fly(): void {} }
class Duck extends FlyingAnimal {}

// Композиція: "Duck HAS-A FlightBehavior" — гнучкіше
interface FlightBehavior { public function fly(): void; }
class Duck { public function __construct(private FlightBehavior $flight) {} }
```

Правило (не лише для PHP): успадковуй, коли є справжнє відношення "є
різновидом" (`is-a`) і поведінка справді спільна для всіх нащадків.
Якщо відчуваєш потребу перевизначати метод порожнім тілом "бо цьому
нащадку воно не підходить" — це сигнал, що потрібна композиція, а не
успадкування.

## 4. Підводні камені

- Забутий `parent::__construct()` — конструктор нащадка **не** викликає
  батьківський автоматично; якщо батьківський конструктор ініціалізує
  важливий стан, забутий виклик залишить його неініціалізованим.
- Глибокі ієрархії успадкування (клас від класу від класу...) складно
  читати й тестувати — у сучасному PHP перевага віддається неглибокому
  успадкуванню + композиції + інтерфейсам (тема 16).
- Перевизначення методу з несумісною сигнатурою (звуження типу параметра,
  а не повернення) — заборонено мовою (порушує принцип підстановки
  Лісков) і кине `Fatal error` при оголошенні класу.

## 5. Сучасний PHP 8.3+

Коваріантність типів повернення (розділ 3.3) — стандартна поведінка з PHP 7.4+,
активно використовується в типізованих fluent-інтерфейсах та фабричних
методах (тема 14), де підклас повинен повертати саме себе, а не базовий тип.

## 6. Контекст екосистеми

Фреймворки (Laravel `Model`, Symfony `AbstractController`) активно
використовують Template Method: базовий клас визначає загальний "скелет"
(як зберегти обʼєкт, як обробити HTTP-запит), а твій клас-нащадок заповнює
конкретні деталі, перевизначаючи окремі методи.
